04

Navegação

Estrutura Expo Router com grupos por role e gating de acesso. O root layout decide o stack pelo estado de auth e pelo role do usuário.

app/ ├── _layout.tsx # gate: auth? → role? → kyc aprovado? ├── (auth)/ │ ├── phone.tsx │ └── verify.tsx ├── (onboarding)/ # só tasker, antes de liberar o app │ └── kyc/ index · document · selfie · pending ├── (tasker)/ # tabs: feed, trampos, perfil │ ├── feed.tsx │ ├── earnings.tsx │ └── profile.tsx ├── (client)/ # tabs: início, meus trampos, perfil │ ├── home.tsx │ ├── post.tsx │ ├── tasks.tsx │ └── profile.tsx └── task/[id]/ # stack modal, role-aware ├── index.tsx # detalhe/aceite | tasker aceitou ├── track.tsx # status / executar ├── payment.tsx # Pix + escrow └── review.tsx
Decisão de arquitetura

Cliente e tasker são quase dois apps. Grupos de rota separados ((tasker) / (client)) compartilhando os componentes base mantêm a navegação limpa sem duplicar o design system. O gating de KYC vive no _layout, não espalhado por tela.

05

Estados & dados

Estados transversais que toda tela de dados precisa tratar. Mockup mostra o estado "cheio" — implementação precisa dos outros três.

EstadoQuandoTratamento
Loadingfetch em andamentoSkeleton dos cards, não spinner solto. Mantém layout estável.
Emptyfeed sem trampos perto · sem ganhos · sem históricoIlustração leve + texto + CTA. Crítico no feed: "amplie o raio" ou "volte mais tarde".
Errorfalha de rede · geo negada · pagamento expiradoMensagem clara + botão "tentar de novo". Geo negada tem fluxo próprio (pedir permissão).
Successaceite, pagamento, avaliação confirmadosFeedback imediato + transição de estado. Sem deixar o usuário em dúvida se funcionou.
Prioridade de implementação

O empty do feed é o estado mais importante do app no início: com pouca liquidez no beta, o tasker vai abrir e ver pouco ou nada. Essa tela precisa segurar o usuário, não frustrar. Não deixe pra depois.

Tempo real

Feed, status do trampo e "tasker aceitou" atualizam via Supabase Realtime. Na UI, isso significa que o estado pode mudar sem ação do usuário — desenhe as transições (ex: card some do feed quando outro tasker aceita) para não parecer bug.
